Call the `dev_status` tool with `action: "render"`. This is the only step — do not run a bash command for this, the tool is always available in a normal session and handles it directly with no permission prompt.

Display its returned text verbatim — do not narrate, do not reformat. The tool always runs with `DEVSTATUS_AGENT=1`, so the item-map line is already suppressed; there's nothing to filter.

If a natural-language reference ("mark 3 done", "work on 2") needs resolving into a slug, call the tool again with `action: "show", slug: "<N>"` — its response includes the item's real `id`. Every mutating action on the `dev_status` tool refuses a numeric `slug`/`secondarySlug` outright and names this exact fix, so there's no separate `--if-rev`/rev-fetching dance to do here at all: resolve with `show`, then mutate with the resolved `id`.

Bash fallback, only if the `dev_status` tool is truly missing from your tool list (e.g. the session was started with `--no-extensions`) — check your actual tool list before assuming this, don't reach for bash just because rendering feels slow or a call seems to be taking a moment: run `DEVSTATUS_AGENT=1 python3 ~/.claude/scripts/dev_status.py render` instead, and note that path applies the classic numeric-position workflow too — a *separate* `render` **without** `DEVSTATUS_AGENT` to read the item-map for `--if-rev` (CLAUDE.md's Backlog section) before any numeric mutation, output for your own resolution use only, never quoted to the user. Mutating commands (`start`, `done`, `update`, `review`, `approve`, `reject`) also default to `DEVSTATUS_AGENT=1` in this fallback path; their stderr resolution echo is suppressed the same way. Numbers shift as items change, so after running one, find the mutated item's own line in the freshly rendered dashboard body and confirm its summary and section match the item the user meant. If they don't, revert (`update <slug> '{"status": "open"}'` or similar), re-render, and ask. For `start`/`done` that same revert still applies; if a `review`/`approve`/`reject` resolved to the wrong item, there is no direct revert — ask the user how to proceed rather than attempting an automatic fix.
