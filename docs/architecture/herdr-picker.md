# herdr-picker

## Boundary and responsibility

`agent-scripts/herdr_picker.py` is the Python twin of
`pi/extensions/swarm-lib/swarm-picker.ts`. It parses `question-tool.ts`'s
rendered option picker (both selection mode and the free-text edit mode) and
matches/navigates it, so that `herdr_delegate.py answer` — the foreman's
supported way to drive a live worker's picker — and the Python test suite share
one implementation with the pi swarm's blocked-relay. It is pure: no module
state, no I/O, no herdr calls. Its input is plain, ANSI-stripped pane text; its
output is data (`ParsedPicker`, `EditMode`, `RenderedOption`) and key sequences.

The two ports are kept deliberately line-for-line parallel: a behavioural drift
is a diff, not a semantics bug. The only deliberate asymmetry is
`navigation_keys`, which returns the arrow prefix only, while the TS
`navigationKeys` still appends `"enter"` (parity is asserted on the prefix).

## Key interfaces

- `parse_picker(content) -> ParsedPicker` — anchors on the LAST picker footer
  and its full-width accent rule, reassembles wrapped option labels keyed off
  the option-number column, strips the edit-mode `✎` marker, skips the editor
  block, and refuses (empty options) on anything non-contiguous.
- `parse_edit_mode(content) -> EditMode | None` — Python-only; recognises the
  `Enter to submit` footer and the editor block, returns options, the marked
  index, the editor text lines, and a `complete` flag (no scroll indicator,
  both borders present).
- `match_option(answer, options) -> RenderedOption | None` — exact, then
  whole-word, then whitespace-stripped matching; never selects the free-text
  escape option and never guesses on ambiguity.
- `navigation_keys(from, to) -> list[str]` — arrow keys only.
- Constants `OTHER_OPTION_LABEL`, `MIN_PARTIAL_ANSWER`.

Both ports iterate `test/fixtures/picker/<name>.txt` plus
`<name>.expected.json`; the `edit-*.txt` fixtures are generated by
`pi/test/render-picker-fixtures.ts` (real pi-tui `Editor.render()`) and read by
the Python suite only.

## Non-goals

- It does not touch herdr, the live pane, or any worker state; `answer`/`watch`
  in `herdr_delegate.py` own that.
- It does not re-implement `question-tool.ts`'s renderer; it parses its output.
- It does not answer non-picker prompts (guard-rails confirmations etc.);
  `parse_picker` refusing them is correct and stays.

## Known unknowns / deferred decisions

- The 2026-10-14 `needs_human` misclassification of a real commit picker is
  reproduced in `needs-human-repro.txt` and recorded as **not a parser bug**:
  the capture had the footer but no opening rule (a read-timing race). The fix
  is `answer`'s bounded poll-until-picker-visible, not a parser change. See
  `test/fixtures/picker/README.md`.
- The editor-block skip is keyed on the literal `"Your answer:"` label and a
  leading-space dash border; if `question-tool.ts`'s edit-mode chrome changes,
  the parser and the render fixture generator must change together (the
  fresh-render check fails loudly otherwise).
