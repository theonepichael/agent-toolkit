## Responsibilities & Boundary

This directory is the GitHub Copilot CLI harness port: generated skills
(`copilot/skills/`), the swarm build output (`copilot/extensions/swarm/`),
hooks (`copilot/hooks/`), and shell aliases (`copilot/aliases.zsh`). It owns
Copilot-specific packaging only — the shared workflow logic these skills
wrap lives elsewhere (`agent-scripts/`, `pi/extensions/swarm-lib/`).

## Hazards & Signposts

- `copilot/skills/*` is generated by `agent-scripts/gen_skills.py` /
  `gen_second_opinion.py` from the shared `templates/*.tmpl` files. Never
  hand-edit a skill here — edit the template or the harness parameter table
  and regenerate; hand-edits are silently overwritten.
- `copilot/aliases.zsh`'s `--allow-tool` pre-approval is broader than it
  looks: Copilot's wildcard matching only works on single-word command
  stems (`git`, `gh`) per `copilot help permissions`, so a per-script
  pattern like `shell(python3 ~/.claude/scripts/dev_status.py:*)` never
  matches. The alias pre-approves `python3` broadly instead — see the
  comment at the top of the file before tightening or copying this
  pattern.
- `copilot/extensions/swarm/` is build output from
  `scripts/build-copilot-swarm.sh`, which bundles
  `pi/extensions/swarm-lib/` — it is not hand-authored here; rebuild via
  that script after changing the shared swarm-lib source.
- Full porting/parity record (confirmed facts, verification results,
  install-state notes) lives in `copilot/CLAUDE_CODE_PARITY.md` — read it
  before changing how a skill or hook behaves relative to Claude Code.

## Local Conventions

No local test tier of its own — Copilot-specific behavior is covered by
`agent-scripts/` tests that assert on generated output for all harnesses
(see `agent-scripts/AGENTS.md`) plus `scripts/test_sync_from_dotfiles.py`
for the shared instructions file. Regenerate skills with
`python3 agent-scripts/gen_skills.py`; rebuild the swarm extension with
`scripts/build-copilot-swarm.sh`.
