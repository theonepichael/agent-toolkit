---
name: skill-drift-audit
description: Audit agent-toolkit's skill docs against the current behavior of the scripts they invoke — stale wording the scripts now contradict, and new script functionality the skills don't use yet — for everything changed since the last audit. Use when the user says 'audit the skills', 'skill drift', 'are the skills stale', 'check the skills against the scripts', or asks after a batch of script changes whether any skills need updating.
argument-hint: [since-ref-or-date]
---

Repo: `R=${AGENT_TOOLKIT_PATH:-$HOME/Workspace/agent-toolkit}`. Steps 1–5 are read-only — run them against `$R`'s main checkout.

## 1. Window
`$ARGUMENTS` (a ref or `YYYY-MM-DD`) sets the start; else the local tag `skill-audit/last` (`git -C "$R" rev-parse -q --verify skill-audit/last`); else ask. The end is `END=$(git -C "$R" rev-parse main)` — record it now; step 7 tags exactly this sha.

## 2. Contract delta
`git -C "$R" diff <start>..$END -- INTERFACES.md agent-scripts/contract_fingerprints.json` is the authoritative list of CLI changes (flags, subcommands, exit codes, env vars, public functions). Add `git log --no-merges --oneline <start>..$END -- agent-scripts/ pi/extensions/` for behavior changes that kept their names — a flag can keep its name while its behavior changes (CLAUDE.md's "Keeping skill docs in sync with their scripts").

## 3. Map to skill sources
For each changed script, `git -C "$R" grep -ln <script-filename>` across the **sources**, never generated copies:
- `templates/*.tmpl`, plus harness-specific wording in `agent-scripts/gen_skills_params.py` and `agent-scripts/gen_second_opinion.py`
- hand-authored commands: `claude/commands/*.md` without the `generated by agent-scripts/gen_` header, plus their per-harness copies (`links.toml` lists them)
- `claude/CORE_INSTRUCTIONS.md`, and Pi tool wrappers that mirror a CLI (`pi/extensions/*-tool.ts`)

## 4. Read through two lenses
Read each changed script's `INTERFACES.md` entry and module docstring, then each mapped source in full. This is a semantic read, not a grep for flag names:
- **Stale**: the source says something the script no longer does (a changed default, a retired path, a failure it now handles differently).
- **Under-used**: the script gained something (a flag, exit code, env var, recovery path) a skill should reach for but doesn't — especially one the script's own error messages point at.
A rule that applies to every toolkit script (e.g. an exit code) belongs once in `CORE_INSTRUCTIONS.md`, not copied into each skill.

## 5. Report — then stop
Group findings as **gaps that matter** / **minor** / **current (no change)**. Each finding names the source file, the script behavior it conflicts with (cite the INTERFACES line or docstring), and the proposed change. Script bugs found along the way get a backlog offer (CLAUDE.md's proactive capture), not a doc workaround. **Always show this report**, even when the audit found nothing to change: with zero findings, the **current (no change)** section reads "no drift found" over the audited window — an explicit result, never a skipped or empty report. Then AskUserQuestion (multiSelect) for which fixes to apply — this is the planning gate; edit nothing before the answer. With zero findings there is nothing to ask, so the gate resolves to "nothing to fix" and step 7 advances the marker.

## 6. Fix
Ad-hoc worktree off `main` (CLAUDE.md's Git section), baseline tests first. Edit sources only, then regenerate: `python3 agent-scripts/gen_skills.py`, `python3 agent-scripts/gen_second_opinion.py`, `python3 agent-scripts/gen_interfaces.py` and `--check` (exit 3 = a doc's shown command no longer matches its script). Where a doc-contract test exists (e.g. `test/test_second_opinion_docs.py`), add a marker for the new rule and run it red before the edit. Full suite (`uv run pytest -q -n auto`), plus `npm --prefix pi test` if `pi/` changed. Commit and land through CLAUDE.md's normal gates.

## 7. Advance the marker
Only once the fixes are merged into `main` — or the user declined all of them — or the audit found **zero findings** (nothing to fix) — run `git -C "$R" tag -f skill-audit/last $END`. Local only: never push it. A failed or abandoned run leaves the tag where it was, so the next run re-audits the same window.
